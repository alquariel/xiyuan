# Slice M Implementation Plan (As-Built): EGM Pressure Path Correction

Date: 2026-11-27

Status: Implementation record. This plan lists the code that was actually added or changed for Slice M, consolidating the 2026-11-24 design and the two 2026-11-25 change notes. The design rationale lives in `docs/design/2026-11-27-afp-abb-cpp-slice-m-egm-pressure-path-correction-design.md`.

**Goal:** Run an in-process EGM pressure path-correction loop inside `AFP_ABB_CPP.exe`, replying to every controller `EgmRobot` with a bounded `EgmSensorPathCorr` Z offset computed from pressure DDS data.

**Architecture:** Dedicated `QThread` owns a blocking UDP server on port 6510. Fast DDS listeners only store latest-value snapshots. A pure PID class computes `z_corr`; a Qt orchestrator owns lifecycle and status. The UI tab edits parameters and shows text status. RAPID CASE 33 wraps the buffered path with EGM path correction behind a FALSE-default switch.

**Tech Stack:** C++17, Qt 6 Core/Network/Widgets/Test, eProsima Fast DDS, CMake, ABB RAPID, Python 3 (host-side test tools only).

struct EgmRobotFrame {

## Task 2: Add The UDP Server

**Files:**
- Create: `src/egm/EgmUdpServer.h`
- Create: `src/egm/EgmUdpServer.cpp`

- [x] **Step 1: Define server config and status**

```cpp
struct EgmUdpServerConfig {
    quint16 listenPort = 6510;
    int controlPeriodMs = 48;     // fallback dt for the first frame
    int correctionAgeMs = 48;
    int receiveTimeoutMs = 500;
    double hardZLimitMm = 3.0;    // final output clamp
};
```

- [x] **Step 2: Implement receive-then-send in `run()`**

- Bind `QHostAddress::AnyIPv4` on the configured port.
- Poll with `waitForReadyRead(25)`.
- Decode each datagram; ignore malformed frames.
- Measure `dt` between frames, clamp to `[0.001, 0.5]` s, use 48 ms for the first frame.
- Call the `CorrectionHandler`, then clamp to `hardZLimitMm`.
- Encode and send one reply to the source address and port.
- Increment `seqno` once per sent frame.
- After `receiveTimeoutMs` without a frame, set `linkTimeout` and send nothing.
- Publish a thread-safe `EgmUdpServerStatus` snapshot after each frame and on timeout.

```cpp
using CorrectionHandler = std::function<double(const EgmRobotFrame&, double dtSeconds)>;
bool run(const CorrectionHandler& handler, QString* errorMessage);
void requestStop();
EgmUdpServerStatus status() const;
```

**Verification:** `noReplyBeforeFirstRobotFrame`, `repliesWithPathCorrectionMessage`, `seqnoIncrementsOncePerFrame`, `clampsCorrectionToHardLimit`, `reportsLinkTimeoutAndStopsReplying`.

## Task 4: Implement The PID Control Law

**Files:**
- Create: `src/egm/PressurePiController.h`
- Create: `src/egm/PressurePiController.cpp`
- Modify: `src/app/AppConfig.h` / `.cpp` (Kd field, added 2026-11-25)
- Test: `tests/test_egm_pressure_pi_controller.cpp`

- [x] **Step 1: Define the pure-logic interface**

```cpp
struct PressurePiConfig {
    double setpoint = 0.0;
    double kp = 0.0;
    double ki = 0.0;
    double kd = 0.0;                 // added 2026-11-25; 0 = PI behavior
    double zMaxMm = 3.0;
    double dzMaxPerCycleMm = 0.1;
    double staleTimeoutMs = 300.0;
    double rampRateMmPerS = 5.0;
};

double update(const PressurePiInput& input, double dtSeconds);
void setConfig(const PressurePiConfig& config);   // keeps integral and output
void reset();
```

- [x] **Step 2: Implement the update path**

- Reject `dt <= 0` and keep the previous output.
- Compute `sampleFresh = valid && age <= staleTimeoutMs`.
- If not enabled or not fresh: clear integral, derivative history, and saturation flag; ramp output toward zero at `rampRateMmPerS`.
- Compute `e = P_mean - setpoint`.
- Derivative on measurement when `kd > 0`, clamped to `±zMax`; zero on the first frame.
- Conditional integration: freeze when the output is saturated and the error drives further saturation.
- Clamp to `±zMax`, then rate-limit each cycle to `±dzMaxPerCycleMm`.
- Store `saturated`, `outputMm`, and `integralTerm`.

Tests cover 13 cases:

```text
zero output when disabled, positive/negative proportional output,
zMax clamp, per-cycle rate limit, integral build-up, integral freeze,
ramp to zero on invalid/stale sample, config hot-update keeping integral,
non-positive dt, derivative reaction, reset clearing derivative state
```

**Verification:** `test_egm_pressure_pi_controller` passes; QtTest reports 15 totals including init/cleanup, corresponding to 13 test functions. Added 2026-11-25: `derivativeReactsToPressureRise`, `resetClearsDerivativeState`.

## Task 5: Add The Orchestrator And Worker Thread

**Files:**
- Create: `src/egm/EgmPressureController.h`
- Create: `src/egm/EgmPressureController.cpp`

- [x] **Step 1: Own the DDS subscribers and UDP server**

The controller constructs `PressureSampleSubscriber`, `RobotMonitorSubscriber`, and `EgmUdpServer` from `EgmPressureConfig`, and copies the PID fields into `PressurePiConfig`.

- [x] **Step 2: Start listening**

`startListening()`:

1. Start both DDS subscribers; on failure, stop the other and return `false` with the error.
2. Reset the PID and last-frame timestamp.
3. Create `QThread` named `EgmUdpServer`; run the blocking server inside it.
4. Set `listening_ = true` and refresh status.

```cpp
serverThread_ = QThread::create([this]() {
    QString error;
    const bool ok = server_.run(
        [this](const EgmRobotFrame& frame, double dt) {
            return computeCorrection(frame, dt);
        },
        &error);
    if (!ok) { /* store workerError_ */ }
});
serverThread_->setObjectName("EgmUdpServer");
serverThread_->start();
```

- [x] **Step 3: Compute correction on the worker thread**

- If the gap since the previous frame exceeds `receiveTimeoutMs`, reset the PID.
- Read a parameter copy under mutex; consume a pending zero request.
- Read the pressure snapshot and build `PressurePiInput`.
- `sampleValid = valid && windowReady && sensorRunning`; pass sample age.
- Return `pi_.update(input, dtSeconds)`.

- [x] **Step 4: Stop safely**

`stopListening()` disables correction immediately, keeps the UDP loop alive for a computed ramp window, then calls `stopWorkerNow()`:

```cpp
const double rampMs = std::min(2000.0, config_.zMaxMm / rate * 1000.0) + 100.0;
QTimer::singleShot(static_cast<int>(rampMs), this, &EgmPressureController::stopWorkerNow);
```

`stopWorkerNow()` requests server stop, joins the thread, stops subscribers, and emits one final status.

- [x] **Step 5: Publish status**

A 100 ms `QTimer` emits `Status` with:

```text
listening, ddsPressureOk, ddsRobotOk, egmConnected, linkTimeout,
correctionEnabled, pressureMean, pressureAgeMs, zCorrectionMm,
robotTcpZ, framesReceived, framesSent, lastError
```

`ddsPressureOk` requires valid, window ready, sensor running, and age within `staleTimeoutMs`.

## Deviations From The Original 2026-11-24 Design

1. **PI became PID.** `Kd` was added on 2026-11-25 with default 0, so existing behavior is unchanged. The derivative is taken on the measurement and clamped to `±z_max`.
2. **The UI has no trend charts.** The two 60 s plots were removed on 2026-11-25; the tab uses text status only.
3. **Correction control uses two buttons.** The single toggle was replaced by "Enable Correction" and "Stop Correction".
4. **No protobuf runtime.** The two fixed messages are hand-encoded and verified against reference Python bytes instead of adding `protoc` and runtime DLLs.
5. **Pose DDS is display-only.** The soft path-deviation interlock described in the early design is not implemented; the robot snapshot feeds `robotTcpZ` in the status only.
6. **Host-side tools were added after the core feature.** They are not part of the shipped application and do not introduce build dependencies.
